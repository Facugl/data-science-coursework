\section{¿Qué es una computadora?}

Una computadora es un dispositivo electrónico, utilizado para procesar información y obtener resultados, capaz de ejecutar cálculos y tomar decisiones a velocidades millones o cientos de millones más rápidas que puedan hacerlo los seres humanos. En el sentido más simple una computadora es ``un dispositivo'' para realizar cálculos o computar. El término sistema de computadora o simplemente computadora se utiliza para enfatizar que, en realidad, son dos partes distintas: hardware y software. El hardware es la computadora en sí misma. El software es el conjunto de programas que indican a la computadora las tareas que debe realizar. Las computadoras procesan datos bajo el control de un conjunto de instrucciones denominadas programas de computadora. Estos programas controlan y dirigen a la computadora para que realice un conjunto de acciones (instrucciones) especificadas por personas especializadas, llamadas programadores de computadoras.

\section{¿Qué es un lenguaje? Dar ejemplos reales}

Un lenguaje es un sistema de comunicación formado por signos, símbolos o reglas que permite expresar ideas, pensamientos, información o instrucciones entre individuos o sistemas.

\textbf{Ejemplos:}
\begin{enumerate}
    \item \textbf{Lenguaje natural (humano):} Son los que usamos diariamente para comunicarnos.
    \item \textbf{Lenguaje matemático:} Utiliza símbolos y números para representar ideas.
    \item \textbf{Lenguaje de programación:} Permite comunicarnos con una computadora.
    \item \textbf{Lenguaje corporal:} Se comunica mediante gestos y expresiones.
\end{enumerate}

Por lo tanto, un lenguaje es cualquier sistema estructurado que permite comunicar información. Puede ser:

\begin{itemize}
    \item Verbal (español)
    \item Simbólico (matemática)
    \item Técnico (programación)
    \item No verbal (gestos)
\end{itemize}

\section{¿Sabe de qué hablamos con la jerarquía de las operaciones?}

La \textbf{jerarquía de operaciones} (también llamada prioridad o precedencia de operadores) es el conjunto de reglas que determinan el orden en que se deben realizar las operaciones en una expresión matemática o de programación.

\subsection{Reglas de jerarquía}

Las operaciones se evalúan en el siguiente orden de mayor a menor prioridad:

\begin{enumerate}
    \item \textbf{Paréntesis \codigo{( )}}: Las expresiones dentro de paréntesis se evalúan primero. Si hay paréntesis anidados (unos dentro de otros), se evalúan desde los más internos hacia los más externos.
    
    \item \textbf{Exponenciación \codigo{\^{}} o \codigo{**}}: Potencias y raíces.
    
    \item \textbf{Multiplicación \codigo{*} y División \codigo{/}}: Tienen la misma prioridad entre sí.
    
    \item \textbf{Suma \codigo{+} y Resta \codigo{-}}: Tienen la misma prioridad entre sí, y son las de menor precedencia.
\end{enumerate}

\subsection{Regla de asociatividad}

Cuando en una expresión coinciden varios operadores con la \textbf{misma prioridad}, se evalúan \textbf{de izquierda a derecha}.

\textbf{Ejemplo:}
\[
8 \div 4 \times 2 = (8 \div 4) \times 2 = 2 \times 2 = 4
\]

\section{¿Cómo se puede alterar la jerarquía natural de las operaciones?}

La jerarquía natural de las operaciones se puede alterar utilizando \textbf{paréntesis}. Los paréntesis tienen la máxima prioridad en cualquier expresión, por lo que todo lo que esté dentro de ellos se evalúa primero, sin importar qué operadores contenga.

\textbf{Ejemplo sin paréntesis:}
\[
5 + 3 \times 2 = 5 + 6 = 11
\]
Aquí la multiplicación se ejecuta primero (jerarquía natural).

\textbf{Ejemplo con paréntesis:}
\[
(5 + 3) \times 2 = 8 \times 2 = 16
\]
Aquí los paréntesis fuerzan que la suma se ejecute primero, alterando la jerarquía natural.

\textbf{Regla práctica:} Cuando queremos que una operación de menor prioridad (como suma o resta) se ejecute antes que una de mayor prioridad (como multiplicación o división), usamos paréntesis para indicarlo explícitamente.

\section{¿Qué es un algoritmo?}

Un algoritmo es un método para resolver un problema mediante una serie de pasos precisos, definidos y finitos.

\begin{itemize}
    \item \textbf{Preciso:} Indica el orden de realización en cada paso.
    \item \textbf{Definido:} Si se sigue dos veces, se obtiene el mismo resultado cada vez.
    \item \textbf{Finito:} Tiene fin; un número determinado de pasos.
\end{itemize}

Un algoritmo debe producir un resultado en un tiempo finito. Los métodos que utilizan algoritmos se denominan métodos algorítmicos, en oposición a los métodos que implican algún juicio o interpretación que se denominan métodos heurísticos. Los algoritmos se pueden expresar por fórmulas, diagramas de flujo y pseudocódigos.

\section{¿Qué es un programa? ¿Qué es un lenguaje de programación? ¿Y qué tarea es la que hace un programador?}

\textbf{¿Qué es un programa?}

Definimos programa como un conjunto de instrucciones y sus tipos. Un programa de computadora es un conjunto de instrucciones -órdenes dadas a la máquina- que producirán la ejecución de una determinada tarea. En esencia, un programa es un medio para conseguir un fin. El fin será probablemente definido como la información necesaria para solucionar un problema.

\textbf{¿Qué es un lenguaje de programación?}

Los lenguajes de programación son todos los símbolos, caracteres y reglas de uso que permiten a las personas "comunicarse" con las computadoras.
Un lenguaje de programación es un sistema estructurado y diseñado principalmente para que las computadoras se entiendan entre sí y con nosotros, los humanos. Contiene un conjunto de acciones consecutivas que el ordenador debe ejecutar.

\textbf{¿Qué tarea hace un programador?}

Un programador es la persona encargada de diseñar, escribir, probar y mantener programas de computadora. Sus principales tareas incluyen:

\begin{itemize}
    \item \textbf{Analizar problemas:} Entender qué problema necesita resolverse y cómo la computadora puede ayudar a solucionarlo.
    \item \textbf{Diseñar soluciones:} Crear algoritmos y planificar la estructura del programa antes de escribir código.
    \item \textbf{Escribir código:} Traducir los algoritmos a un lenguaje de programación específico que la computadora pueda ejecutar.
    \item \textbf{Probar y depurar:} Ejecutar el programa para encontrar y corregir errores (bugs).
    \item \textbf{Mantener y actualizar:} Mejorar programas existentes, agregar nuevas funcionalidades o adaptarlos a nuevas necesidades.
\end{itemize}

En resumen, el programador actúa como traductor entre las necesidades humanas y el lenguaje que entiende la computadora, transformando problemas del mundo real en soluciones computacionales.

\section{¿A qué se denomina un programador Full-Stack?}

Un programador \textbf{Full-Stack} (o de ``pila completa``) es un desarrollador que tiene conocimientos y habilidades tanto en el \textbf{frontend} (la parte visible de una aplicación) como en el \textbf{backend} (el servidor y la lógica de negocio).

\textbf{Frontend:} Es lo que el usuario ve e interactúa directamente. Incluye:
\begin{itemize}
    \item Diseño de interfaces (HTML, CSS)
    \item Interactividad y comportamiento (JavaScript)
    \item Experiencia de usuario (UX/UI)
\end{itemize}

\textbf{Backend:} Es la parte del servidor que procesa datos y lógica. Incluye:
\begin{itemize}
    \item Servidores y APIs
    \item Bases de datos
    \item Lógica de negocio y seguridad
    \item Lenguajes como Python, Java, Node.js, PHP
\end{itemize}

Un programador Full-Stack puede trabajar en todas las capas de una aplicación web, desde el diseño de la interfaz hasta la gestión de bases de datos, lo que le permite desarrollar aplicaciones completas de forma independiente. Esta versatilidad lo hace muy valioso en equipos pequeños o startups, aunque en proyectos grandes suele especializarse en alguna de las dos áreas.

\section{¿Qué fases en la ``resolución de problemas'' conoce? Mencionelas, seleccione la que le parezca más le llame la atención explicando su importancia y sumando un ejemplo}

El proceso de resolución de un problema con una computadora conduce a la escritura de un programa y a su ejecución en la misma. Aunque el proceso de diseñar programas es, esencialmente, un proceso creativo, se puede considerar una serie de fases o pasos comunes que generalmente deben seguir todos los programadores.

\subsection{Fases de la resolución de problemas}

Las fases principales son:

\begin{enumerate}
    \item \textbf{Análisis del problema}: Se analiza el problema teniendo presente la especificación de los requisitos dados por quien encarga el programa.
    
    \item \textbf{Diseño del algoritmo}: Una vez analizado el problema, se diseña una solución que conducirá a un algoritmo que lo resuelva.
    
    \item \textbf{Codificación (implementación)}: La solución se escribe en la sintaxis del lenguaje de alto nivel elegido (por ejemplo, Python, Java o C) y se obtiene un programa fuente.
    
    \item \textbf{Compilación y ejecución}: El programa se traduce a lenguaje máquina y se ejecuta.
    
    \item \textbf{Verificación}: Se comprueba rigurosamente que el programa funcione correctamente.
    
    \item \textbf{Depuración}: Se eliminan todos los errores (denominados ``bugs'') que puedan aparecer.
    
    \item \textbf{Mantenimiento}: El programa se actualiza y modifica cada vez que sea necesario, de modo que se cumplan todas las necesidades de cambio de sus usuarios.
    
    \item \textbf{Documentación}: Escritura de las diferentes fases del ciclo de vida del software, manuales de usuario y de referencia, así como normas para el mantenimiento.
\end{enumerate}

\subsection{Fase que más me interesa: Análisis y Diseño}

Las fases que considero más importantes son las \textbf{dos primeras}: el \textbf{análisis} y el \textbf{diseño del algoritmo}. Estas etapas son donde realmente se resuelve el problema de forma conceptual y lógica.

Una vez que se tiene claro \textit{qué} hay que hacer y \textit{cómo} hacerlo (el algoritmo), la codificación es relativamente sencilla: se trata simplemente de traducir esa solución a la sintaxis del lenguaje de programación elegido. Es decir, la parte difícil no es programar, sino \textbf{pensar la solución}.

Si el análisis y diseño están bien hechos, el código prácticamente ``se escribe solo''. En cambio, si estas fases se hacen mal, por más que se domine la sintaxis del lenguaje, el programa no resolverá correctamente el problema.

\subsection{Ejemplo práctico}

\textbf{Problema:} Calcular el promedio de calificaciones de un estudiante y determinar si aprobó (promedio $\geq$ 6).

\textbf{1. Análisis del problema:}
\begin{itemize}
    \item \textit{Entrada:} Lista de calificaciones del estudiante
    \item \textit{Proceso:} Sumar todas las calificaciones y dividir por la cantidad
    \item \textit{Salida:} Promedio y mensaje de ``Aprobado'' o ``Desaprobado''
    \item \textit{Condición:} Si promedio $\geq$ 6 entonces aprobó
\end{itemize}

\textbf{2. Diseño del algoritmo:}
\begin{enumerate}
    \item Leer la cantidad de calificaciones ($n$)
    \item Inicializar suma en 0
    \item Para cada calificación:
    \begin{itemize}
        \item Leer la calificación
        \item Sumarla al total
    \end{itemize}
    \item Calcular promedio = suma / $n$
    \item Si promedio $\geq$ 6:
    \begin{itemize}
        \item Mostrar ``Aprobado''
    \end{itemize}
    \item Si no:
    \begin{itemize}
        \item Mostrar ``Desaprobado''
    \end{itemize}
    \item Mostrar el promedio
\end{enumerate}

\textbf{3. Codificación} (en este punto, ya solo traducimos el algoritmo):

\begin{lstlisting}[style=python, caption={Ejemplo en Python}]
# La logica ya esta resuelta, ahora solo escribimos sintaxis
n = int(input("Cantidad de calificaciones: "))
suma = 0

for i in range(n):
    calificacion = float(input(f"Calificacion {i+1}: "))
    suma += calificacion

promedio = suma / n

if promedio >= 6:
    print("Aprobado")
else:
    print("Desaprobado")
    
print(f"Promedio: {promedio}")
\end{lstlisting}

Como se puede observar, una vez que se completaron las fases de análisis y diseño, la codificación fue directa: simplemente se tradujo la lógica ya pensada a la sintaxis de Python. El verdadero trabajo intelectual ocurrió en las dos primeras fases.

\section{¿Qué es una variable y qué es una constante?}

\textbf{Constante:}

Una constante es un espacio en memoria cuyo valor \textbf{no puede cambiar} durante la ejecución del programa. Se define una vez y permanece fija.

\textbf{Ejemplo:} \codigo{PI = 3.1415926}, \codigo{IVA = 0.21}

\textbf{Variable:}

Una variable es un espacio en memoria identificado por un nombre simbólico, cuyo valor \textbf{puede cambiar} durante la ejecución del programa.

\textbf{Ejemplo:} \codigo{edad = 20}, luego \codigo{edad = 21}

\textbf{Diferencia clave:} Las constantes mantienen su valor fijo, mientras que las variables pueden modificarse cuantas veces sea necesario durante la ejecución del programa.

\section{¿Qué es Software y qué es Hardware?}

\textbf{Hardware:}

El hardware es la parte \textbf{física y tangible} de una computadora. Son todos los componentes que se pueden tocar.

\textbf{Ejemplos:} Procesador (CPU), memoria RAM, disco duro, teclado, mouse, monitor, placa madre.

\textbf{Software:}

El software es la parte \textbf{lógica e intangible} de una computadora. Son los programas e instrucciones que le indican al hardware qué hacer.

\textbf{Ejemplos:} Sistema operativo (Windows, Linux), navegadores web, Microsoft Word, videojuegos, aplicaciones móviles.

\textbf{Relación:} El hardware es el ``cuerpo'' de la computadora y el software es el ``cerebro''. Ambos son necesarios: el hardware sin software no puede hacer nada útil, y el software necesita hardware para ejecutarse.

\section{¿Qué es la memoria RAM y la memoria ROM?}

\textbf{Memoria RAM (Random Access Memory - Memoria de Acceso Aleatorio):}

Es una memoria \textbf{volátil} y \textbf{temporal}. Almacena datos y programas que se están ejecutando en ese momento. Cuando se apaga la computadora, toda la información en la RAM se pierde.

\textbf{Características:} Lectura y escritura rápida, se borra al apagar el equipo, mayor capacidad (4GB, 8GB, 16GB, etc.).

\textbf{Memoria ROM (Read Only Memory - Memoria de Solo Lectura):}

Es una memoria \textbf{no volátil} y \textbf{permanente}. Almacena instrucciones básicas necesarias para iniciar la computadora (BIOS). Su contenido no se borra al apagar el equipo.

\textbf{Características:} Solo lectura (no se puede modificar fácilmente), mantiene información sin energía, menor capacidad.

\textbf{Diferencia principal:} La RAM es rápida pero temporal (se borra sin energía), mientras que la ROM es permanente pero más lenta (conserva la información sin energía).

\section{Nombrar las unidades principales de un procesador}

Un procesador (CPU - Unidad Central de Procesamiento) está compuesto por tres unidades principales:

\begin{enumerate}
    \item \textbf{Unidad de Control (UC):} Se encarga de controlar y coordinar todas las operaciones del procesador. Interpreta las instrucciones del programa y genera las señales necesarias para ejecutarlas.
    
    \item \textbf{Unidad Aritmético-Lógica (ALU):} Realiza todas las operaciones aritméticas (suma, resta, multiplicación, división) y lógicas (comparaciones, AND, OR, NOT).
    
    \item \textbf{Registros:} Son pequeñas unidades de memoria de alta velocidad dentro del procesador que almacenan temporalmente datos e instrucciones que se están procesando en ese momento.
\end{enumerate}

Estas tres unidades trabajan en conjunto para ejecutar las instrucciones de los programas: la UC coordina, la ALU calcula, y los registros almacenan datos temporales durante el procesamiento.
